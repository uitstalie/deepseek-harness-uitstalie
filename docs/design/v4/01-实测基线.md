# 01 实测基线

测量对象：本机运行中的 DSH 0.2.3-alpha.3，窗口 1,048,576，模型 deepseek-flash，preset cordis。dev 检出 HEAD `bdde29cac7` 与安装包 16/16 个包字节一致（见 dev 报告 P7），所以下面的数就是运行中行为。

## 1. 预占（首轮请求）

| 块 | token | 占首轮 |
|---|---:|---:|
| 工具 schema | 15,058（super 45 个）/ 15,650（dev 47 个） | 74.7% / 56.9% |
| 系统提示 | 2,506 / 2,570 | 12.4% / 9.3% |
| AGENTS.md + 规则 | super 无大块 / dev 4,609 | — / 16.7% |
| 技能目录 | ~449 / 1,975 | ~2% / 7.2% |
| 运行快照 + 时间 + 任务 | ~600 / 857 | ~3% / 3.1% |
| provider 封装差额 | 未拆（dev 1,861） | — / 6.8% |

- 首轮 prompt：super 会话 20,151；dev 会话 27,522。
- 工具 schema 是系统提示的约 6 倍；5 个 `workspace_*` 工具占 dev 工具税 36%。
- 首轮缓存不保证：同 preset 前缀被别的会话暖过则 72.1% 命中，冷前缀 0.5%。

## 2. 每轮重发与缓存

- **没有差分请求**：每步重建全量历史 + 系统提示 + 工具，整包发出；省的是 provider 前缀缓存。
- 累计命中率：98.76% / 99.64% / 99.00%（三个样本会话）。
- 前缀一变（系统提示更新、压缩），`cacheRead` 掉回约 19,968（工具 + 系统那一段），其余全价重发。

## 3. 压缩

- 两把尺子：派发规则 30% = 314,573；harness 自动阈值 727,040 = `min(0.8×窗口, 窗口−256k−64k)`，自动保留 126,812。
- 实测：自动 726,504 → 194,973（−73%）；手动 retain=0 550,760 → 18,345（−96.7%）。
- 本机 super 会话 11 次压缩全是手动（12 条 `compact` 命令）；dev 样本里有 3 次自动。
- 摘要由 LLM 生成，结构化八段（Primary Request / Key Technical Concepts / Files and Code / Errors and Fixes / Pending Jobs / Current Work / Next Step / Critical Context）。
- 压缩按 seq 区间整体替换，记 `shadowedRange` / `shadowedSeqs` / `shadowedTokenCount`。

## 4. 压缩掉的内容构成（11 次压缩，合计约 190 万 token，估算口径）

| 块 | token | 占比 |
|---|---:|---:|
| 助手推理（thinking） | 731,539 | 38.4% |
| 工具结果 | 604,344 | 31.7% |
| 工具参数（call arguments） | 359,494 | 18.9% |
| 注入块 | 70,406 | 3.7% |
| 助手正文 | 61,671 | 3.2% |
| 用户原话 | 40,734 | 2.1% |
| 系统提示 | 36,009 | 1.9% |

- 工具参数里：`pwsh` 152k、`write` 90.5k、`edit` 31.6k、`workspace_sessions` 30k、`workspace_message` 14k、`workspace_tasks` 11k。
- 工具结果里：probe（查会话、git、目录、grep、glob）占被压总量 10.2%，`read` 8.5%，`exec` 7.4%。
- 推理会被重放：`llm-deepseek/src/serialize.ts:32-35` 把历史 assistant 的 reasoning 原样作为 `thinking` 重发。

## 5. 重复与卸载代价

- 2,330 条工具结果里 324 条是完全相同的重复调用（同一条命令跑 24 次、同一个会话 get 15 次），约 99k token。
- 重复率 14%。这说明"卸载后重查"的代价真实存在，设计时要把重查算进去。
- 中间删一块会破前缀缓存，卸载是"省上下文不省钱"；单次 prune 的重发尾长还没实测。

## 6. 机制上的硬约束

- 删除只有两处：compaction（seq 段 + 摘要）和 pruner（>8,192 字符，只在压缩事务里跑）；`compaction/prune` 事件类型已具备。
- 工具 schema 是全局固定块，不能按任务装；唯一杠杆是 role（subagent < agent < super）和 preset。
- 事件里没有 agent-role，只有 message role；注入块与跨代理来信都是 `user` 消息，靠 `source.kind` 区分。
- memory 只收全局事实，业务状态进不去。
