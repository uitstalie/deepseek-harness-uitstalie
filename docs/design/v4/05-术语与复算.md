# 05 术语与复算

## 术语

| 词 | 含义 |
|---|---|
| 预占 | 首轮请求里系统提示 + 工具 schema + 注入的固定部分 |
| 决策行 | 一次判断加派发的记录，压缩后的最小单位（时间 / 诉求 / 判断 / 目标 / 结果） |
| 状态卡 | 工作区级的当前状态摘要，跨会话传递 |
| 装载 / 卸载 | 把一段信息放进上下文；用完换成指针，走 `compaction/prune` |
| probe | 查工作区、会话、文件的一次性探查：`workspace_*`、`grep`、`glob`、git/目录命令、`read` |
| 推理重放 | 历史 assistant 的 thinking 块每轮原样发给模型（`serialize.ts:32-35`） |
| 两把尺子 | 派发规则的 30%（314,573）与 harness 自动压缩阈值（727,040），不是一回事 |

## 复算脚本

都在 `D:\dqc\superAgent\tmp\`，只读：

| 脚本 | 作用 |
|---|---|
| `session-inspect.js <log> raw` | 解压会话日志，事件类型统计、首尾样本、usage |
| `session-deep.js <log>` | 工具 schema 体量、系统提示字符数、逐轮 prompt 曲线、压缩清单、角色统计 |
| `unload-probe.js <log>` | 当前 surface 按 Probe/Read/Exec/Agent/Other 分类的可卸载量、重复调用、surface 估算 |
| `unload-ranges.js <log>` | 每次压缩的 probe/read/exec 占比、重复调用总量 |
| `unload-compose.js <log>` | 压缩内容按块类型（推理/参数/结果/正文/注入）的构成 |
| `tool-dump.js <log>` | 从 `request/header` 导出全部工具名、schema 字节、描述（→ 06-工具分类表 的数据源） |

## 数字口径

- 文中 token 分两种：带"估算"字样的是 harness 自己的 `chars/4` 启发式（`token-meter/src/estimate.ts`）；不带的是 provider 回传的 usage。
- 字符→token 比不稳定：代码约 3.9 字符/token，含中文或 JSON 的约 2.0–3.3，所以只按 4 估会偏高。
- 百分比优先看构成比例，绝对 token 数以 provider usage 为准。
