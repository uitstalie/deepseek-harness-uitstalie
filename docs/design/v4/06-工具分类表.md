# 06 工具分类表

目的：给"角色档位"配工具面时对齐用。每个工具标四件事——分类、给哪个档位、`minRole` 现状、schema 体量。数据来自本机 super 会话（47 个工具，68,432 字节 ≈ 15,058 token）。

## 读法

- **super / 子档位 / 无**：该档位要不要装。`无` = 不进任何档位（连 super 也可疑）。
- **分类**按用途，不按包名。派发权类单独一列——这是 03 第 5 条（子代理收派发权）的依据。
- 体量是 schema JSON 字节数（`request/header` 实测），token ≈ 字节 ÷ 4.2。

## 数字结论

| 档位 | 工具数 | schema 字节 | ≈token |
|---|---:|---:|---:|
| 现状 super（全装） | 47 | 68,432 | ~15,058 |
| 建议子档位（fs+shell+技能+后台读） | 14 | ~6,100 | ~1,400 |
| 削减 | −33 | −62,300 | **−13,700** |

- 五个 `workspace_*` 合计 16,094 字节（≈3,700 token），是工具税最大单项；只给有派发权的档位。
- 子档位首轮估算：系统提示（精简后 ~1.5k）+ 工具 ~1.4k + 注入 ~1k ≈ **4–5k token**，对上 03 第 5 条的 7–8k 估计（还有 AGENTS.md 注入的浮动）。

## 维护约定

1. 新工具进 profile 时先在这张表加行、定档位，再谈 preset 落位。
2. 分类冲突时优先看"子代理该不该有"，再看"super 要不要"。
3. preset 落位后，此表加一列"落在哪个 preset 文件"，与 `bundle/web-app/presets/*.patch.yml` 对齐。
4. `minRole` 列来自代码现状（03/04 已定：档位化后此列退役，工具面归 preset 配置）。
