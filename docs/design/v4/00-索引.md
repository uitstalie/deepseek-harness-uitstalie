## 一句话结论

Super Agent 先做，但设计按**角色档位**建、不按 `super` 写死（role 将来可能由其他途径确定，super 只是第一个实例；承载物就是 agent preset）。它的"工作区信息"= 用户诉求 + 判断 + 派发目标；推理压成决策行，执行痕迹用完就卸。工作区会话随后：一任务一会话，靠工作区状态卡传递。common（append-only 日志、回放、压缩）保留，只在 surface 上加"可撤销的装载块"。

## 关键决策（到今天为止）

1. 档位承载物 = agent preset；开档定档、运行中不换（`agent-preset/locked` 是设计选择，接受）。
2. 子代理：fork 接续用继承；spawn 独立任务用精简子档位（收工具面、收派发权）；专家档位走 `allowedAgentPresets` 白名单。
3. `minRole` 三值词表在档位化后退役，工具面归 preset 配置。
4. 决策行在派发那一刻写；判断含否掉的选项；闭环行归档案，未闭环行常驻。
5. 目标形态是超级节点图（07）：人只操作 super agent，super 控制其余节点；循环有预算，到线回人。reviewer 是独立只读档位，不是 actors 自查。
6. 存储统一到 `~\.dsh\workspace\`（注册表退化为索引 + 工作区五件套）；推理/决策走热/温/冷三层温度模型——推理过期的是可达性不是数据，决策行 append-only 并带冷层指针；task 记录只存决策引用（不塞可变记录）。冷层回读已验证：`tool-session-query` 未挂载且授权按 cwd 严格相等，跨工作区没有受支持通道（08 §3.1）。一单一 task 一会话（analyze 反例的解）。
