## Scope: single-Host only

DSH does not provide Host-to-Host coordination. `packages/api/gateway/README.md` defines Client-to-Host calls and streams; `packages/api/remotes/README.md` assembles typed Host capabilities for Client consumers; and `packages/api/remote-access/README.md` uses Peer for a client principal. These APIs do not coordinate two Hosts.

The ownership evidence is consistent: `packages/superagent/superagent-core/README.md:58` says one instance is not a cross-process lock; `packages/experimental/liveshare/README.md:164` says cross-Host coordination is absent and each home should have one active Owner Host; `goal/jira-ledger-assessment-2026-11-08.md:317` describes Windows' named kernel semaphore and warns against two Hosts writing one Session; and `packages/schedule/schedule/tests/targets.spec.ts:480` shows `session/writer-held` / "another Host writes it" rejecting a second writer.

Sharing one home across multiple Hosts is unsupported. The only guaranteed shape is one Host, so "two-Host end-to-end verification" is outside scope, not an outstanding obligation.

P0-1's scope is the single-Host journal and its per-task lease; it does not promise distributed exactly-once delivery. P1-4 is resolved by disabling and superseding the ACL backend, not marked Partial.
