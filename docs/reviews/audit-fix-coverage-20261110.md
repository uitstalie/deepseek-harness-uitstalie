## Evidence and commands

The evidence was collected from the source checked out on 2026-11-10 after the report loop and dispatch domain moves. No implementation was changed for this review. A current line number identifies a mechanism, not a claim that its real Host lifecycle was exercised.

The main behavior command was:

```sh
pnpm exec tsx --test --test-isolation=none packages/jira/jira-agent/src/schema.test.ts packages/jira/jira-agent/src/index.test.ts packages/jira/jira-agent/src/dispatch-reports.test.ts packages/superagent/superagent-core/src/dispatch-store.test.ts packages/jira/jira-agent/src/superagent.test.ts packages/superagent/superagent-core/src/index.test.ts
```

It passed **175 tests, 0 failed, 0 skipped**, including the named tests cited below. The moved dispatch-store path replaces the obsolete Jira path. A separately reported package-wide run had one temporary Git `index.lock` failure in `creates a tag through the tool, then tags an issue with it`; its temporary directory was removed by the test teardown, and the same case passed in the cited 175-test run. It is not evidence of a dispatch change, and no fixture or assertion was modified.

The sandbox command was `pnpm exec vitest run --config .dsh/vitest-sandbox-local.config.ts`; `acl-disabled.spec.ts` passed **2 tests, 0 failed**. Those tests inject the Windows platform and prove refusal without creating grants, not a replacement Windows confinement backend or attribution of the historical ACEs.

No real two-Host delivery, process crash/restart, injected production failure, current Host UI inspection, or live ACL attribution experiment was run. `unverifiable` below means that the required evidence is absent from this review; it does not negate a static code fact.

## Fixed-looking items with weaker evidence

- **P0-4 / K-6 / A-4:** the new binding and refused-admission handling are directly present and the named test passed, but a real long-turn abort followed by a crash, archive, or late settlement was not exercised.
- **P1-3 is not fixed:** listing exposes more fields, but `inspect` still rejects a Session without a live Agent; the running-session test does not cover a cold Session.
- **P1-5 / K-7 / A-5 / A-9:** current domain/projection tests pass, but live field-by-field comparison and multi-process recovery were not run.
- **J-18:** the real composition test passes, but it does not measure the separately deployed Host's effective configuration.
- **P0-3 is deliberately partial rather than fixed:** saved-report recovery and retry are real, yet a pending binding without saved text is skipped, startup recovery is not awaited on dispose, and the real Host restart/failure-injection evidence requested by the re-review is absent.

The largest remaining hazards are cross-process duplicate report claims, completed/no-text turns being treated as returned business results, and non-quiescent startup/dispose behavior. The first can duplicate user-visible work, the second misstates the task outcome, and the third leaves recovery incomplete precisely during lifecycle transitions.
