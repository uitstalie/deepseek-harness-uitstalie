<a id="what-changed"></a>
## 做了什么

- 安全自动修复及其直接暴露的修补共减少 100 条，其中包括修复器误删后必须恢复的 `Block` 断言。
- 仅源码的一轮减少 31 条：4 条有意处理的 promise，27 条冗余字符串转换。
- 测试轮在 63 个测试文件的 1,048 个 `no-floating-promises` 表达式前插入 `void`，未碰任何源码文件。
- 四个源码小组清掉剩余 53 条安全项：store-atom、persona-card、jira-core 与 jira-cli、jira-agent 与 UI。
- 两处按行窄 disable 覆盖 `ToolDefinition.execute`，该接口要求返回 Promise；去掉 `async` 会改变返回契约。

<a id="why-the-remaining-findings-stay"></a>
## 为什么保留剩余项

541 条测试项描述的是测试注册与 fixture 形状，不是线上行为。机械改写会产生远大于收益的 diff，因此把它们保留为已知噪声底。

22 条源码 `no-unnecessary-condition` 是信任边界上的运行期防御，覆盖持久化 JSON、模型参数和平台 timer。为了变绿删除检查，就是拿真实防御路径换一个好看的计数。

两处契约 disable 是有意的：必须返回 Promise 的 `execute` 不能去掉 `async`，否则会改变 ToolDefinition 接口。

<a id="known-traps"></a>
## 已知坑

不要再整仓跑 `lint:fix`。它的安全修复会误删实际必要的类型断言，它的 void 清理也会把有意的抑制变成未使用表达式。

`no-floating-promises` 与 `no-meaningless-void-operator` 在本仓库的测试注册上语义冲突。测试 promise 必须按规则单独处理或按精确位置插入，然后重跑完整 lint，证明没有新增 `no-meaningless-void-operator`。

<a id="open-contract-work"></a>
## 待迁移的契约

memory summary 仍读取已废弃的 `snapshotEvents`；要消除 `no-deprecated`，需要先迁移到替代 API。

`serviceOf<T>` 的导出泛型只使用一次；删除它会改变可调用签名，需要 API 决策，不是 lint 编辑。
